# Проверка и сохранение сущностей

Python / FastAPI, SQLite и локальная модель через LM Studio. Четыре отдельных скрипта и промпта выделяют и нормализуют сведения о людях, организации, ИП и электронные средства коммуникации. Для каждого человека отдельно извлекаются фамилия, имя, отчество, дата и место рождения. Телефоны пока не включены. Модель не должна разворачивать неизвестные инициалы или придумывать реквизиты.

## Запуск

Требуется Python 3.12 и LM Studio на компьютере, где выполняется Python сервер. Используйте существующий checkout, без создания дополнительного worktree.

1. Установите LM Studio с https://lmstudio.ai/.
2. Скачайте модель с поддержкой инструкций и русского языка, например Qwen2.5-7B-Instruct в формате GGUF. Выбор размера и квантования зависит от памяти компьютера.
3. Загрузите модель и включите локальный сервер в разделе Developer. Стандартный адрес API: `http://127.0.0.1:1234/v1`.
4. Получите идентификатор модели через `GET /v1/models` и задайте его в `LM_STUDIO_MODEL`.
5. Установите зависимости и запустите приложение:

```bash
cd /workspace/1
python -m venv .venv
.venv/bin/pip install -r requirements.lock
export LM_STUDIO_MODEL="идентификатор-модели-из-LM-Studio"
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для Windows PowerShell используйте `.venv\Scripts\python.exe`, `.venv\Scripts\pip.exe` и `$env:LM_STUDIO_MODEL="идентификатор-модели"`; запуск: `.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000`.

Откройте веб интерфейс на порту 8000 своего компьютера. `LM_STUDIO_URL` меняет базовый адрес API (включая `/v1`). При включённой авторизации сервера задайте `LM_STUDIO_API_KEY` в окружении; не записывайте ключ в код. Клиент использует `/chat/completions` и структурированный JSON по схеме. Выберите модель и runtime с поддержкой структурированных ответов; ошибки не заменяются нестрогим распознаванием.

Если Python приложение работает в облаке, `127.0.0.1` обозначает облачную машину, а не ваш компьютер. Для локальной обработки документов запускайте Python приложение и LM Studio на одном компьютере. Удалённое подключение требует отдельно настроенного доступного адреса и защиты соединения; само по себе включение LM Studio на ПК не даёт облаку доступ.

## Проверка оператором

Загрузите TXT (UTF-8 или Windows-1251), DOCX или PDF с текстовым слоем. Максимум 20 МБ и 300 000 символов. DOC и OCR пока не поддерживаются. Для DOCX читаются абзацы и таблицы; колонтитулы и текстовые блоки не извлекаются.

ФИО подсвечиваются синим, организации зелёным, ИП оранжевым, коммуникации фиолетовым. При пересечении сущностей фрагмент получает цвет первой категории, а подсказка перечисляет все результаты. Нажатие на подсветку выбирает строку таблицы. В таблице можно менять категорию, нормализованное значение, замечание и границы фрагмента. Исходный текст не редактируется. Для добавления выделите текст мышью и нажмите «Добавить».

До OK информация находится только в памяти процесса, а не в SQLite. Не перезапускайте сервер во время проверки. Неактивные временные документы удаляются при следующем обращении через час. Отмена удаляет временный документ. После подтверждения кнопка скрывается; повторная отправка того же подтверждения возвращает прежний ID, без новых строк.

## База данных

Файл: `data/entities.sqlite3`; каталог меняется через `DATA_DIR`. Исходный бинарный файл не сохраняется — хранится извлечённый текст.

- `documents`: `id`, уникальный `review_token`, `filename`, `format`, `text`, `uploaded_at`, `confirmed_at`, `operator`, `model`, `original_result` (первоначальный ответ для аудита). Время — Unix timestamp. `operator` пока NULL: авторизация не реализована.
- `entities`: `id`, `document_id`, `kind`, `normalized_value`.
- `mentions`: `id`, `entity_id`, `original_text`, `start`, `end`, `note`, `field`. Поле `field` указывает ФИО, дату или место рождения; для остальных категорий — `entity`. Позиции — индексы Unicode символов; конец не включается.

Каждое подтверждённое упоминание получает отдельную запись сущности: совпадение ФИО не означает одного человека. Автоматическое связывание людей/организаций между документами не производится. ИНН/ОГРНИП пока не выделяются отдельными полями.

- `person_details`: `entity_id` (связь с сущностью), `surname`, `given_name`, `patronymic`, `birth_date`, `birth_place`. Неизвестные поля хранятся как SQL NULL. Полная дата — ДД.ММ.ГГГГ, неполная сохраняется без дополнения. Место рождения точно повторяет исходный фрагмент. При первом подтверждении схема базы дополняется без удаления прежних документов. Старые ФИО не разбиваются на компоненты автоматически.

## Проверки

```bash
.venv/bin/python -m pytest -q
curl --fail http://127.0.0.1:8000/
curl --fail http://127.0.0.1:1234/v1/models
```

Тесты проверяют сохранение, исправления, отсутствие записи до OK, повторное подтверждение и обработку файлов. В тестах используются подставные ответы LLM: это не проверка качества реальной модели. После подключения модели обязательно загрузите документ с известными ФИО, организацией, ИП и email, проверьте подсветку, исправьте результат и подтвердите сохранение.

Приложение рассчитано на локальную работу одного оператора: один worker, без `--reload` во время проверки. Авторизация, многопользовательская изоляция, постоянная очередь задач и просмотр ранее сохранённых документов пока отсутствуют. Не публикуйте сервер в открытом интернете. Для резервного копирования используйте SQLite backup API или копируйте базу при остановленном сервере.

## Промпт и проверка сведений о человеке

`prompts/persons.txt` возвращает массив объектов с русскими ключами `фамилия`, `имя`, `отчество`, `дата_рождения`, `место_рождения`, `исходные_фрагменты`. Последний содержит `фио`, `дата_рождения`, `место_рождения` — точные цитаты или null. Другие категории сохраняют формат ответа `{"entities": [...]}`.

В интерфейсе у каждого человека редактируются пять полей. Пустая строка превращается в null. Исходные фрагменты ФИО, даты и места рождения подсвечиваются синим и связаны с одной строкой человека. Можно изменить границы каждого фрагмента или выделить правильный текст мышью и нажать «Привязать выделенный текст». При удалении фрагмента соответствующие значения очищаются. Для ручного добавления человека компоненты ФИО заполняются оператором: программа не угадывает их. Для заполненного поля требуется исходный фрагмент.

Если цитата встречается несколько раз, выбирается первое вхождение в обрабатываемом фрагменте с предупреждением проверить привязку. Скрипт не переносит дату и место на все одинаковые ФИО. Результаты с разными сведениями или привязками не объединяются автоматически. Связь сведений с конкретным человеком определяет модель и подтверждает оператор; программная проверка существования цитаты не доказывает такую связь.

## Ошибки распознавания

На странице показываются этап обработки и конкретная причина: недоступный сервер, тайм-аут, HTTP-статус, незавершённый ответ, неверный JSON или отсутствующий исходный фрагмент. При HTTP 400 проверьте журнал LM Studio: идентификатор модели, размер контекста и поддержку JSON-схемы. Ответы сервера и содержимое документов не выводятся в диагностические сообщения.

Тайм-аут одного запроса — 180 секунд. Если журнал подтверждает нормальную, но медленную генерацию на CPU, можно увеличить его, например в PowerShell: `$env:LM_STUDIO_TIMEOUT="600"`. Допустимы значения от 1 до 3600 секунд. Увеличение тайм-аута не исправляет неправильный адрес, ошибку схемы или нехватку контекста.
