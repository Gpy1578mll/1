# Запуск с YandexGPT API на Windows

Python веб приложение и SQLite остаются на компьютере. Текст документов и отдельные промпты отправляются в Yandex Cloud. LM Studio, llama.cpp и ключ Gemini для этого режима не нужны.

## Подготовка Yandex Cloud

1. Откройте https://console.yandex.cloud/ и создайте или выберите облако и каталог.
2. Проверьте состояние платёжного аккаунта, условия тарифа YandexGPT и наличие пробного гранта. Не рассчитывайте на постоянную бесплатную работу: она не гарантируется. Приложение не включает биллинг и не ограничивает расходы аккаунта на стороне провайдера.
3. Скопируйте **ID каталога** (folder ID), в котором будет использоваться модель. ID облака, проекта, сервисного аккаунта или платёжного аккаунта не заменяет ID каталога.
4. Создайте сервисный аккаунт с правами на выполнение запросов к языковым моделям в этом каталоге. Для Foundation Models используется роль `ai.languageModels.user`; проверьте актуальные требования в документации Yandex Cloud.
5. Создайте для сервисного аккаунта **API-ключ** с областью действия для выполнения запросов к языковым моделям/Foundation Models. Для Python сервера нужен секретный API-ключ, а не ID ключа, не IAM-токен, не OAuth-токен и не ключ Gemini. Не присылайте секрет в чат и не добавляйте его в GitHub.

Актуальная документация: https://yandex.cloud/ru/docs/ai-studio/ . Регистрация платёжного аккаунта и предоставление прав выполняются в вашем аккаунте Yandex Cloud; приложение этого не делает.

## Обновление и запуск

1. Остановите прежний Python сервер через Ctrl+C.
2. Скачайте свежий архив проекта с GitHub, распакуйте в отдельную временную папку и скопируйте исходники в `C:\Projects\1-main`, сохранив существующие `.venv312` и `data`. Новые Python зависимости не требуются.
3. Откройте `start-yandex.bat` двойным щелчком. Если BAT не запускается, используйте PowerShell:

```powershell
cd "C:\Projects\1-main"
.\.venv312\Scripts\python.exe .\scripts\start_yandex.py
```

Сценарий запросит ID каталога и секретный ключ скрытым вводом, затем проверит доступ через `tokenizeCompletion` на коротком тестовом тексте. Это не генерация результата и не проверка качества/JSON-вывода выбранной модели. После проверки запустится веб приложение на порту 8000. На странице должна появиться надпись **YandexGPT API: текст документа отправляется Yandex Cloud**.

По умолчанию используется `yandexgpt/latest`. Для другой доступной модели до запуска задайте, например:

```powershell
$env:YANDEX_MODEL="yandexgpt-lite/latest"
```

Это пример идентификатора; поддержка JSON-схемы и цена зависят от модели и версии. Обработчик не снимает требование JSON-схемы при ошибках. Полный URI формируется как `gpt://<YANDEX_FOLDER_ID>/<YANDEX_MODEL>`.

Ключ не сохраняется в файлы или SQLite. При следующем запуске его нужно ввести снова, если он отдельно не задан в окружении. На Windows нужны уже установленные Python 3.12 и Visual C++ x64 для PyMuPDF.

## Переменные окружения

| Имя | Назначение |
|---|---|
| `LLM_PROVIDER` | `yandex`; сценарий запуска устанавливает автоматически |
| `YANDEX_FOLDER_ID` | ID каталога Yandex Cloud |
| `YANDEX_API_KEY` | Секретный API-ключ сервисного аккаунта |
| `YANDEX_MODEL` | По умолчанию `yandexgpt/latest` |
| `YANDEX_TIMEOUT` | Тайм-аут запроса, по умолчанию 180 секунд; допустимо от 1 до 3600 |

Адрес API фиксирован: `https://llm.api.cloud.yandex.net/foundationModels/v1/completion`. Авторизация — `Authorization: Api-Key ...`; заголовок `x-data-logging-enabled: false` запрашивает отключение логирования данных у провайдера. Условия хранения и обработки данных проверяйте в Yandex Cloud: наличие заголовка само по себе не является гарантией всех условий конфиденциальности.

## Проверка

Загрузите небольшой TXT с вымышленными ФИО, датой рождения, организацией, ИП и email. Проверьте выделение четырьмя промптами, нормализацию, подсветку, исправление оператором и сохранение по OK. В `documents.provider` сохраняется `yandex`, в `model` — полный URI модели. До OK записи в SQLite нет.

HTTP 401 — проверьте секретный ключ; 403 — права аккаунта, каталог, ограничения ключа и биллинг; 400 — каталог, модель или JSON-схему при генерации; 429 — квоты. Автоматических повторов, переключения на другие сервисы и обхода фильтров нет. При обработке документов содержимое ответа сервера и API-ключ не выводятся в диагностические сообщения.

Запросы и ответы программно проверены с подставным Yandex API. Реальная авторизация и распознавание ещё требуют ваших реквизитов и локального запуска. BAT имеет ASCII-содержимое и окончания CRLF; его выполнение на Windows из облачной Linux-среды не проверено.

## Если HTTP 400 возникает до запуска веб сервера

Это ошибка предварительного запроса `tokenizeCompletion`; он не содержит JSON-схему. Обновлённый запуск показывает этап и очищенное сообщение Яндекса, чтобы различать ошибки каталога, ключа и модели. Ключ и длинные похожие на токены идентификаторы скрываются. Только эта проверка с фиксированным тестовым текстом показывает сообщение провайдера; ошибки обработки документов не раскрывают полный ответ API.

Проверка также обрабатывает текстовые ответы и другие структуры JSON. Если сервер не передал пояснение, появляется сообщение «пустой ответ сервера»; одна ошибка HTTP 400 не позволяет установить точную причину.

Убедитесь, что YANDEX_FOLDER_ID совпадает с ID каталога в URL консоли `/folders/<ID>/dashboard`, а YANDEX_MODEL имеет вид `yandexgpt/latest`, а не полный `gpt://...` URI. Сценарий формирует полный URI автоматически.
